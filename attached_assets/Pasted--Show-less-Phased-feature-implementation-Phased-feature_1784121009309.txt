1. Auth Header Logic
The existing generated API client in lib/api-client-react uses a customFetch wrapper (lib/api-client-react/src/custom-fetch.ts) which includes logic to attach a Bearer token via an _authTokenGetter. However, for web applications, the project explicitly follows a cookie-based authentication strategy. Documentation within the codebase (.local/skills/clerk-auth/references/setup-and-customization.md) confirms:

Web: Uses Clerk session cookies automatically sent by the browser for same-origin requests. Explicit Authorization headers are discouraged.
Mobile/Expo: Uses setAuthTokenGetter to attach bearer tokens manually.
Since this is a web frontend (artifacts/mithra-ai), you should not manually attach Authorization: Bearer headers. Instead, ensure your fetch call includes credentials: 'include' (or 'same-origin' if strictly same-origin) to allow cookies to be sent.

2. Clerk Session Token Utility
If you must use a bearer token (e.g., for a non-same-origin backend or specific requirement), use the useAuth hook from @clerk/react.

Hook: const { getToken } = useAuth();
Usage: const token = await getToken();
Existing components like App.tsx already import from @clerk/react, though they primarily use useUser and useClerk.

3. Credentials and Cookie Mode
The backend (artifacts/api-server) uses clerkProxyMiddleware.ts and standard Clerk Express integration, which validates sessions via cookies in a web context.

Mode: same-origin / include cookies.
Transport: Standard fetch without explicit headers for web, or Bearer tokens for mobile.
Code Snippet for New Frontend Pages
import { useAuth } from "@clerk/react";
import { useQuery } from "@tanstack/react-query";
export function useMyNewRoute() {
  const { getToken } = useAuth();
  return useQuery({
    queryKey: ['new-route'],
    queryFn: async () => {
      // NOTE: For same-origin web, headers/getToken are usually unnecessary 
      // as cookies are sent automatically.
      const response = await fetch('/api/new-endpoint', {
        method: 'GET',
        // include if backend is on a different subdomain/origin
        credentials: 'include', 
        headers: {
          'Content-Type': 'application/json',
          // Only if bearer token is required:
          // 'Authorization': `Bearer ${await getToken()}`
        }
      });
      if (!response.ok) throw new Error('Network response was not ok');
      return response.json();
    }
  });
}
